# Changelog

## Unreleased 0.3.0 - 2026-10-29

The current source adopts Numera Gen MCP and `numera-gen-mcp`, adds explicit per-model media kinds
and transformation modes, and authors fal queue orchestration for image, video, audio and 3D outputs.
The ten legacy image tools remain alongside `generate_media` and `get_media_output_info`.
Maintained Python/JavaScript tooling is being ported to a separate Rust workspace; the original
sources remain until equivalent behavior is qualified, and the five PowerShell scripts stay unchanged.

These changes are uncompiled and unexecuted. Current lockfile resolution, formatting, assertion parity,
six-target runtime/package verification and genuine signatures remain required before release.
A separate manual source-preparation route resolves/formats candidate source without tests or signing
inputs. Existing-key signing on `main` is authorized but has not run for this candidate.
The installation guide uses the published 0.2.0 archive and its actual legacy executable/template;
current-source examples and media declarations do not upgrade that binary.

## Native 0.2.0 - 2026-10-26

Rust replaces the production runtime while preserving ten tools, provider wire contracts, private
configuration and durable SQLite receipts/original image bytes. Six published Windows/Linux/macOS
x64/ARM64 archives need no Node, Python, Rust compiler or launcher. Direct `bridge`, optional authenticated
loopback HTTP on configurable port1969, a native menu and separate optional `numera-dev` are included.
Native Windows/macOS signatures are independently required during activation; Windows child exit codes
retain all32 bits. Comfy orchestration stays in the service layer, separate from pure wire mapping.

Exact `f253557` / run `40244894089`, attempt2, passed all sixteen jobs, all470 frozen cases/50 suites
and85.7791% region/83.3426% branch coverage. All six genuine publisher-signature positive/negative,
signed maintenance and extracted SDK checks passed. Original CI archives were published without
rebuilding/repacking; the downloaded Windows x64 Release passed pinned signatures and ten-tool readiness.
[Verification and trust limits](docs/releases/0.2.0.md) distinguish self-signed identity from public OS
trust/notarization, and actual owner-host cutover from CI/isolated readiness. Old runtime/data remain
until the owner switches the entry and verifies the real native connection.

## Historical TypeScript changes - 2026-10-05

Authoritative upstream failures/cancellation now close lifecycle capacity through fenced transitions.
Empty orphan allocations release unused journal reservations without deleting uncertain receipts.
Targeted cancellation distinguishes backend dispatch from confirmed terminal status; retained originals
and storage recovery remain independent. MCP client/server update together to2.3.1.
Real two-host stdio acceptance covers terminal states and restarts. Concurrent initial WAL setup handles
bounded database lock contention, and explicit original-job recovery can publish completed images after
local wait cancellation without another generation request.

Use the stable native TypeScript7 compiler for typecheck/build alongside the official TypeScript6
API compatibility package for type-aware ESLint. Explicit compiler paths avoid executable collisions;
normal dependency resolution and existing verification gates remain enforced.

Recovery changes passed hosted Windows/Linux/macOS validation on320f903. Renewable
writer fencing and a bounded private result journal preserve received originals for storage recovery
without paid resubmission. Output index/receipt relationships commit together, with stable publication
hash reconciliation. Directory creation handles verified competing directories safely. Scalar JSON
editing rejects excess references instead of dropping them. Persisted aspect/tier evidence drives the
same original-dimension checks in normal and recovered completion. Capability discovery exposes
sourced Flash/Pro/GPT Image limits separately from route safety ceilings and account availability.

## Previous changes - 2026-10-03

Simple private endpoint/key/model-list configuration with friendly display names, portable defaults
and adjacent-file discovery. Existing advanced settings remain supported. Linux/macOS setup docs,
macOS CI matrix and new POSIX permission/symlink/process-group assertions. Larger README logo.
Correlated tool start/completion/failure logs, immutable event/run metadata and safe diagnostic timing.
Selectable arbitrary API prefix, generic Images default and optional compact Responses profile with
separate orchestration model. Per-model output format/size/quality defaults and public root template.
Three consistent model slots with inactive placeholders and nullable provider-default settings.
Neutral public paths and setup instructions for Codex, Kiro, Cursor, Hermes, OpenCode and other MCP
clients. One authorized real Images generation verified; no all-model/editing/GUI claim.
Env configuration and validated save-without-restart model updates, with immutable active-job
snapshots and endpoint/account-bound recovery. Explicit in-image translation and rectangular native
mask editing reuse the existing edit tool; original bytes and native dimensions remain unchanged.

Explicit model-based upscale through existing reference editing, with larger-size input validation
and honest output deviations; no local resizing or automatic provider fallback.

Large Base64 image validation no longer overflows the runtime stack; byte limits and strict alphabet/
padding validation remain enforced. Native4K output was verified on one authorized gateway/model call.

Model capability discovery now separates built-in ratio suggestions, documented native dimension
presets and actual route acceptance; unknown models/custom sizes remain explicitly unknown.
