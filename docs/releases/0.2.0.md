## Trust and activation boundaries

[Signing](../SIGNING.md) records the independently pinned key/certificate and validity. This is a
project-approved self-signed identity, not public OS trust, Apple Developer ID or notarization.
There is no external cryptographic timestamp. Windows PowerShell can report an untrusted-root chain;
independent pinned Authenticode verification succeeds. No trust store or keychain preference is changed.
macOS signing was verified on macOS15+ hosted runners; older OS compatibility is not established.

Packaged status documents were frozen before the successful signing run and may say signing or
Release is pending. This exact-source verification supersedes those status statements; signed archive
bytes remain unchanged. Online documentation can be newer than the binary build source.

Actual owner-host reconnection is separate from CI/isolated readiness. Keep the working installation,
private configuration, original images, receipts and migration snapshots until that connection is
verified. GUI preview rendering, live-provider quality and GPU execution are not claimed. Unknown
paid outcomes are never resubmitted. A missing historical test-first execution record remains a
process-evidence limitation; passing current tests does not reconstruct that history.
