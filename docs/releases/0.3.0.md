- Signed Install/Update/Register/Remove passed all six targets, including both Windows locked-member

  rebuilding or repacking. Each manifest signature is independently authenticated against the pinned key.

## Host practical checks

The downloaded Windows x64 Release passed current-host pinned Authenticode/manifest verification,
both version commands and the checks below. Every command ran from the extracted archive, never from
inside the installation root, and no provider call was made.

- `setup Install` into an isolated root produced a 402-member manifest for `0.3.0` /
  `x86_64-pc-windows-msvc` / `7601b53`. Installed `bin/numera-gen-mcp.exe --version` reports the same
  version, source and signer, with `Trust: self-signed; not public OS trust or Apple notarization`.
- `setup Update` with identical bytes completed in 5.4s with every maintenance postcondition: private
  files preserved, lock released, no staging directory retained. Running the updater from inside the
  root it replaces fails by design, because a running executable cannot overwrite itself.
- `setup Diagnose` against a fixture config pointing at an unreachable endpoint reported
  `local_ready: true`, `credentials_ready: true`, `tool_count: 12`, `generation_verified: false`,
  empty blockers, and a null `connection_ready` because no provider was contacted.
- A real `bridge` stdio session answered `initialize` with protocol version `2025-06-18` and
  `serverInfo numera-gen-mcp 0.3.0`, listed twelve tools, returned an empty resource list and exited
  cleanly with code 0.

No owner-host configuration entry, credential, provider probe or paid submission was added or used.
The existing 0.2.0 installation remains in place as the rollback.

## Trust and activation boundaries

[Signing](../SIGNING.md) records the independently pinned key/certificate and validity. This is a
project-approved self-signed identity, not public OS trust, Apple Developer ID or notarization.
There is no external cryptographic timestamp. Windows PowerShell can report an untrusted-root chain;
independent pinned Authenticode verification succeeds. No trust store or keychain preference is changed.
macOS signing was verified on hosted runners; older OS compatibility is not established.

Actual owner-host reconnection is separate from CI/isolated readiness. Keep the working installation,
private configuration, original images, receipts and migration snapshots until that connection is
confirmed on real host hardware.
